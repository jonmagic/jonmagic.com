Wasp Architecture

Architecture

Wasp provides sandboxed Linux VM workspaces for multi-agent AI coding on macOS. It is built in Swift 6.0 using Apple’s Virtualization.framework and ships as both a CLI tool and a SwiftUI desktop app.

This document walks through the system layer by layer, from the high-level structure down to the networking internals that make SSH-into-a-VM feel seamless.

Diagrams are authored in D2 and live in docs/diagrams/. Edit the .d2 source files and re-render with d2 --pad=40 input.d2 output.svg.

High-Level Structure

Wasp is organized into three build targets that share a common library:

Target What it is Key dependency
WaspLib Shared library — all business logic, VM management, networking, view models Virtualization.framework, Observation
wasp CLI executable swift-argument-parser
WaspApp SwiftUI macOS app SwiftTerm, (optional) Ghostty

Both the CLI and the GUI import WaspLib and delegate all real work to it. Neither contains business logic of its own — they are thin presentation layers.

Dependencies

Apple frameworks: - Virtualization.framework — creates and runs ARM64 Linux VMs with virtio devices - Observation — @Observable macro for reactive view models (no Combine) - Foundation — file I/O, process spawning, JSON codable - CryptoKit — SHA-256 checksums for disk image integrity - SwiftUI + WebKit — GUI only

Third-party: - swift-argument-parser (1.5+) — CLI subcommand routing - SwiftTerm (1.2+) — terminal emulator views for SSH and serial console - Ghostty (optional) — GPU-accelerated terminal via C library; excluded from SPM builds, compiled only via XcodeGen with a bridging header

WaspLib — The Core Library

WaspLib contains all of the domain logic, organized into five functional areas plus a set of view models that bridge to the GUI.

Workspace Management

The workspace is the central user-facing concept — a named, persistent sandbox with its own disk image, SSH key, and VM configuration.

Type Role
WorkspaceManager Orchestrator. Composes storage, disk, SSH, and VM managers. Exposes create/list/destroy/start/stop.
WorkspaceStorage Persists WorkspaceConfig as JSON files. Owns all workspace directory paths.
WorkspaceConfig Codable value type — name, VM settings, SSH key name, image reference. Supports backward-compatible decoding.
WorkspaceStatus Enum: stopped, starting, running, stopping, error.
WorkspaceSummary Lightweight DTO for list views (name + status + config summary).

VM Layer

This layer wraps Apple’s Virtualization.framework behind protocol boundaries so the rest of the app never touches VZ* types directly.

Type Role
VMConfiguration Plain value type — CPU count, RAM bytes, disk path, MAC address.
VZConfigurationBuilder Maps VMConfiguration into a full VZVirtualMachineConfiguration. Creates EFI boot loader, NAT network, virtio socket device, and a serial port backed by a pty socket pair. Returns a VMBuildResult that retains the file handles.
VMInstance @MainActor class wrapping VZVirtualMachine. Handles start/stop and delegate callbacks. Must live on the main thread (Virtualization.framework requirement).
VMState State machine enum with a canTransition(to:) method that enforces valid state changes.
VMLifecycleManager Implements VMLifecycleManaging protocol. Maintains a dictionary of RunningVM instances keyed by workspace name, protected by OSAllocatedUnfairLock.
RunningVM Holds a running VM’s instance, build result (file handles), and SSH proxy relay together so they share a lifecycle.
VMDelegate VZVirtualMachineDelegate conformance — translates delegate callbacks into state updates.

Serial Console

The serial console provides the initial communication channel with the guest VM before SSH is available. It is used for automated provisioning.

Type Role
SerialConsole Bidirectional byte stream over a pty. Uses two background Thread objects running poll(2) loops for non-blocking I/O.
SerialExpect Pattern-matching engine for serial output — waits for expected strings, then sends responses. Like the Unix expect tool.
GuestProvisioner Uses SerialExpect to log in as root, inject an SSH public key, and start the SSH daemon. Implements VMProvisioning protocol.

SSH and Networking

Wasp avoids TCP entirely for host-to-guest communication. Instead, it uses virtio sockets (vsock) — a paravirtualized transport that doesn’t require IP networking. SSH traffic flows through a chain of relays.

Type Role
SSHKeyManager Wraps ssh-keygen to generate ed25519 key pairs. Stores keys in .keys/ directory.
SSHConnector Builds the ssh command-line arguments including a ProxyCommand that routes through a Unix domain socket.
SSHProxyRelay Listens on a Unix domain socket. For each incoming connection, creates a VsockProxy to bridge to the guest’s vsock port 22. Uses a background Thread with a poll(2) accept loop.
VsockProxy Bidirectional file-descriptor relay using poll(2). Copies bytes between a Unix socket fd and a vsock fd.
VZSocketDeviceConnector Adapter that wraps VZVirtioSocketDevice behind the VsockConnecting protocol for testability.
IPResolver Resolves the guest VM’s IP address by polling DHCP lease files and falling back to ARP table parsing. Used for NAT-based networking when vsock isn’t sufficient.
DHCPLeaseParser Parses /var/db/dhcpd_leases to find IP-to-MAC mappings.
ARPResolver Parses arp -an output as a fallback for IP resolution.
PortForwarder Forwards a single local TCP port to a vsock port on the guest.
PortForwardManager Manages multiple PortForwarder instances for a workspace.

Image Pipeline

Wasp uses a layered disk image system: base images are downloaded, golden images are prepared (provisioned base images), and workspace images are cloned from golden images.

Type Role
ImageStore Manages the directory layout: base/, golden/, manifests/. Owns all image paths.
ImageManifest Codable metadata tracking an image’s lineage — base URL, SHA-256 hash, creation date, provision script used.
BaseImageDownloader Downloads base Linux images over HTTP with checksum verification (CryptoKit SHA-256). Implements HTTPFetching protocol.
ImagePreparer Orchestrates the base-to-golden build: boots a VM from the base image, provisions it via serial console, shuts down, and saves the result as a golden image.
ImageBaker Copies a workspace’s modified disk image back into the golden image store (“baking” customizations into a reusable template).
ProvisionScriptManager Loads provisioning shell scripts and performs environment variable substitution before injection.
DiskImageManager Clones golden images to create workspace disk images. Implements DiskImageCloning protocol.

View Models

All view models live in WaspLib (not in WaspApp) so they can be tested without a UI. They use the @Observable macro from Swift’s Observation framework and are annotated @MainActor.

Type Role
WorkspaceListModel Central app state. Holds the list of workspaces, selected workspace, auto-refresh timer. Owns TabManager instances per workspace.
TabManager Per-workspace tab state — terminal, serial, and browser tabs with drag-and-drop reordering.
PaletteModel Quick-open and command palette with subsequence matching (VS Code-style).
CreateWorkspaceViewModel Form state for workspace creation (name, image, CPU, RAM).
WorkspaceSettingsViewModel Form state for editing workspace settings.
BakeImageViewModel Drives the “bake image” workflow.
ImageListViewModel Lists and manages available golden images.
PortForwardViewModel Manages port forwarding rules for a workspace.
BrowserTabViewModel Manages in-app browser tab state (URL, port-forward target).

VM Lifecycle — From Create to SSH

When a user creates and starts a workspace, a carefully sequenced pipeline runs:

  1. Clone disk image — DiskImageManager copies the golden image to create a fresh workspace disk.
  2. Build VM configuration — VZConfigurationBuilder assembles the full VZVirtualMachineConfiguration: CPU, RAM, disk, NAT network, virtio socket device, serial port (backed by a pty socket pair), and EFI boot loader.
  3. Boot — VMInstance starts the VZVirtualMachine on the main thread.
  4. Attach serial console — SerialConsole connects to the pty and begins reading output via poll(2).
  5. Provision — GuestProvisioner uses expect/send patterns over the serial console to log in, inject the workspace’s SSH public key, and start the SSH daemon.
  6. Start SSH relay — SSHProxyRelay opens a Unix domain socket and begins accepting connections.
  7. Ready — The workspace is now accessible. The GUI can open terminal tabs that spawn ssh processes connecting through the Unix socket.

SSH Connectivity — How Terminal Tabs Work

The path from a terminal tab to a shell session inside the VM is the most intricate part of the system. No TCP is used — everything flows through virtio sockets.

The chain:

  1. TerminalTabView (SwiftTerm) spawns a local ssh process.
  2. The ssh process is configured with a ProxyCommand that connects to a Unix domain socket on the host filesystem.
  3. SSHProxyRelay accepts the connection on the Unix socket. For each connection, it asks VZVirtioSocketDevice to connect to vsock port 22 on the guest.
  4. A VsockProxy is created to bidirectionally relay bytes between the Unix socket fd and the vsock fd, using poll(2) in a tight loop.
  5. Inside the guest, sshd receives the connection on vsock port 22 and authenticates using the ed25519 key that was injected during provisioning.

This design avoids NAT/port-forwarding complexity entirely. Each workspace gets its own Unix socket, so multiple VMs can run simultaneously without port conflicts.

SwiftUI App — View Architecture

The GUI uses a NavigationSplitView with a sidebar/detail layout. A key design decision is using ZStack with opacity toggling (not conditional rendering) for tab content, so that NSViewRepresentable terminal views are never destroyed when switching tabs — preserving scrollback history and SSH connections.

View Preservation Pattern

// WorkspaceDetailView uses ZStack + opacity, not if/else
ZStack {
    ForEach(tabs) { tab in
        tabView(for: tab)
            .opacity(tab == selectedTab ? 1 : 0)
    }
}

This is critical because SwiftUI’s NSViewRepresentable lifecycle destroys the underlying NSView when removed from the view hierarchy. A terminal tab holds a live SSH process — destroying and recreating it would kill the session.

Data Flow

  • WaspApp creates a WorkspaceListModel and injects it into the SwiftUI environment.
  • WorkspaceListModel is the single source of truth for all workspace state.
  • Views observe @Observable view models via SwiftUI’s automatic dependency tracking.
  • User actions flow through view models into WorkspaceManager, which delegates to the appropriate subsystem manager.

Ghostty Integration (Optional)

The project includes an optional GPU-accelerated terminal backend using Ghostty’s C library. This code requires a bridging header and is excluded from SPM builds — it only compiles through the XcodeGen-generated Xcode project. Files live in Sources/WaspApp/Ghostty/.

Concurrency Model

Wasp uses Swift 6.0 strict concurrency throughout. The key patterns:

Pattern Where Why
@MainActor VMInstance, all view models Virtualization.framework requires main thread; SwiftUI requires main actor for UI state
OSAllocatedUnfairLock VMLifecycleManager, SSHProxyRelay, PortForwardManager Thread-safe mutable state in types that are @unchecked Sendable
Background Thread SerialConsole, SSHProxyRelay, VsockProxy Blocking poll(2) I/O loops that cannot use structured concurrency
async/await VM lifecycle, IP resolution, image downloads Non-blocking operations that integrate with Swift’s task system

The split between Thread and async/await is intentional: poll(2) blocks the calling thread indefinitely, which would starve the cooperative thread pool if run in a Task. Dedicated threads solve this.

Testing Strategy

Tests use Swift Testing (@Test, @Suite, #expect) with protocol-based dependency injection. Every manager protocol has a corresponding test double:

Protocol Test Double What it mocks
DiskImageCloning MockDiskImageCloner Disk image copy operations
SSHKeyManaging MockSSHKeyManager Key generation and loading
VMLifecycleManaging MockVMLifecycleManager VM boot/stop
VsockConnecting MockVsockConnector Virtio socket connections
VMProvisioning MockProvisioner Serial console provisioning
HTTPFetching MockHTTPFetcher Image downloads

The test suite covers all WaspLib types (37 test files). CLI integration tests run the built wasp binary as a subprocess.
